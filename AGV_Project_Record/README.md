# ESP32 디지털 트윈 AGV 프로젝트 전체 기록

- 기록 작성일: 2026-08-04
- 프로젝트: ESP32 + TB6612FNG + MG310P20 엔코더 모터 2개 기반 2륜 차동구동 AGV
- 개발 환경: PlatformIO / Arduino framework / ESP32 Dev Module / 115200 baud
- 이 문서의 목적: 지금까지의 대화를 그대로 나열하기보다, 다음 작업 때 곧바로 이어갈 수 있도록 대화 내용, 배선, 시험 과정, 문제 원인, 확정 수치, 안전 절차와 최종 코드를 구조화하여 보존한다.

> 이 문서는 채팅의 모든 문장을 그대로 복사한 원문 로그는 아니다. 대신 실제 제작에 필요한 기술적 내용과 대화 흐름을 빠짐없이 재구성한 프로젝트 인수인계 기록이다.

## 1. 현재 상태 한눈에 보기

현재 AGV의 기본 구동부는 정상 작동한다.

- 왼쪽 및 오른쪽 모터 개별 구동 확인 완료
- 양쪽 엔코더 A/B 신호 확인 완료
- 양쪽 엔코더 방향 부호 정규화 완료
- 모터 전진 방향 확인 완료
- 배터리 전원만으로 ESP32와 모터 구동 확인 완료
- 바퀴 1회전 카운트 측정 완료
- RPM 측정 및 140 RPM PID 시험 완료
- 15 cm 및 30 cm 직진 시험 완료
- 시계방향 90도 및 반시계방향 90도 회전 시험 완료
- `30 cm 직진 → 시계방향 90도 → 30 cm 직진` 자동 L자 경로 시험 완료

현재 최종 업로드·검증된 동작은 다음과 같다.

```text
30 cm 전진
→ 1초 정지
→ 시계방향 90도 제자리 회전
→ 1초 정지
→ 30 cm 전진
→ 자동 정지
```

최종 코드는 [final_l_route_main.cpp](./final_l_route_main.cpp)에 보관했다.

## 2. 프로젝트 목표

최종 목표는 실제 AGV와 PC상의 가상 AGV가 같은 위치와 방향을 공유하는 디지털 트윈이다.

단계별 목표는 다음과 같다.

1. 모터를 안전하게 구동한다.
2. 엔코더로 바퀴 이동량과 방향을 읽는다.
3. 양쪽 바퀴 속도를 맞춘다.
4. 이동거리와 회전각을 제어한다.
5. 엔코더로 `X`, `Y`, `방향각`을 계산한다.
6. Wi-Fi로 위치와 상태를 PC에 전송한다.
7. PC 디지털 트윈 화면에서 실제 AGV와 동일하게 움직이게 한다.

현재는 4단계까지 실제 바닥 시험을 완료한 상태다.

| 부품 | 확인된 내용 |
|---|---|
| ESP32 | ESP32-WROOM-32E DevKit 계열 |
| ESP32 어댑터 | 나사 체결식 터미널 어댑터 |
| 모터 드라이버 | TB6612FNG 듀얼 DC 모터 드라이버 |
| 왼쪽 모터 | WHEELTEC MG310P20 7.4 V 엔코더 기어드 모터 |
| 오른쪽 모터 | WHEELTEC MG310P20 7.4 V 엔코더 기어드 모터 |
| 엔코더 | 13-line Hall encoder |
| 감속비 | 20:1 |
| 바퀴 | 지름 48 mm 고무바퀴 2개 |
| 캐스터 | 보조 캐스터 바퀴 |
| 배터리 | 보호회로 내장형 18650 3.7 V 셀 2개 |
| 배터리 홀더 | 18650 2구 직렬 홀더, 2S 구성 |
| 강압모듈 | ZX-052 V2.0 / LM2596 계열 표시창 장착 모듈 |

배터리는 3.7 V 셀 2개의 직렬 구성이므로 명목 전압은 7.4 V다. 충전 상태에 따라 실제 팩 전압은 달라질 수 있다. 모터에는 배터리 전압을 공급하고, ESP32에는 강압모듈에서 만든 5.0 V를 공급한다.

2S 리튬이온 팩은 완충 시 약 8.4 V까지 올라갈 수 있다. 배터리 원전압을 ESP32의 `5V` 또는 `3V3` 단자에 직접 연결하면 안 된다.

## 4. 모터 한 개의 선 색상과 역할

왼쪽과 오른쪽 모터 모두 같은 색상 구성을 사용한다.

| 선 색상 | 표기 | 역할 |
|---|---|---|
| 빨간색 | M+ | DC 모터 한쪽 단자 |
| 초록색 | M- | DC 모터 반대쪽 단자 |
| 파란색 | VCC | 엔코더 전원 |
| 검은색 | GND | 엔코더 접지 |
| 흰색 | A | 엔코더 A 채널 |
| 노란색 | B | 엔코더 B 채널 |

주의할 점은 빨간색과 초록색은 모터 전력선이고, 파란색·검은색·흰색·노란색은 엔코더용 선이라는 것이다.

## 5. 최종 전원 구조

### 5.1 전원 흐름

```text
18650 2S 배터리 홀더 빨간선(+)
 ├─> 강압모듈 VIN+
 └─> TB6612 VM

18650 2S 배터리 홀더 검은선(-)
 ├─> 강압모듈 VIN-
 └─> TB6612 GND

강압모듈 VOUT+ (5.0 V) ─> ESP32 5V
강압모듈 VOUT-         ─> ESP32 GND

ESP32 3V3 ─> TB6612 VCC
ESP32 GND ─> TB6612 GND 및 양쪽 엔코더 GND
```

모든 제어 신호가 같은 기준 전압을 사용하려면 ESP32, TB6612, 엔코더, 배터리 음극이 공통 GND가 되어야 한다.

### 5.2 강압모듈

- 입력: 18650 2S 배터리
- 출력 설정값: `5.0 V`
- `VOUT+`: ESP32 `5V`
- `VOUT-`: ESP32 `GND`
- TB6612 `VM`에는 강압된 5 V가 아니라 배터리 입력 전압이 들어간다.

강압모듈을 처음 조절할 때 표시를 `OUT`으로 맞춘 뒤 가변저항을 여러 바퀴 돌려 5.0 V로 맞췄다. 부하를 연결한 뒤에도 표시가 약 5.0 V로 유지되고 ESP32가 재부팅되지 않는 것을 확인했다.

### 5.3 현재 임시 배선의 주의점

현재 `VIN+` 나사 단자에 다음 빨간선 2개가 같이 들어간 구조다.

1. 배터리 홀더의 빨간색 `+`선
2. TB6612 `VM`으로 가는 빨간색 분기선

`VIN-` 쪽에도 배터리 음극과 TB6612 GND 분기가 연결되어 있다.

이 구조에서 실제로 VIN+ 선 하나가 풀린 적이 있다. 다시 연결한 뒤 각 선을 한 가닥씩 살짝 당겨 단단함을 확인했다. 그러나 이는 임시 구성이다.

추후 반드시 다음과 같이 정식 마감한다.

- `+` 전원 분배단자
- `-` 전원 분배단자
- 전원 스위치
- 적절한 퓨즈
- 배터리, ESP32, TB6612, 강압모듈의 차체 고정
- 피복 밖으로 나온 구리선 제거

정식 마감 전에는 사람이 옆에서 보는 짧은 시험만 수행한다.

## 6. TB6612와 ESP32 제어 배선

| TB6612 | ESP32 GPIO | 역할 |
|---|---:|---|
| PWMA | GPIO27 | 왼쪽 모터 PWM |
| AIN1 | GPIO25 | 왼쪽 모터 방향 1 |
| AIN2 | GPIO26 | 왼쪽 모터 방향 2 |
| STBY | GPIO13 | 드라이버 활성화 |
| BIN1 | GPIO33 | 오른쪽 모터 방향 1 |
| BIN2 | GPIO32 | 오른쪽 모터 방향 2 |
| PWMB | GPIO14 | 오른쪽 모터 PWM |
| VCC | ESP32 3V3 | TB6612 로직 전원 |

```cpp
ledcWrite(LEFT_PWM_CHANNEL, 0);
ledcWrite(RIGHT_PWM_CHANNEL, 0);
```

## 7. TB6612와 모터 출력 배선

| 모터 | 모터선 | TB6612 출력 |
|---|---|---|
| 왼쪽 | 빨간색 M+ | AO1 |
| 왼쪽 | 초록색 M- | AO2 |
| 오른쪽 | 빨간색 M+ | BO1 |
| 오른쪽 | 초록색 M- | BO2 |

최종 확인된 방향 논리는 다음과 같다.

| 동작 | AIN1 | AIN2 | BIN1 | BIN2 |
|---|---:|---:|---:|---:|
| 두 바퀴 전진 | LOW | HIGH | HIGH | LOW |
| 두 바퀴 후진 | HIGH | LOW | LOW | HIGH |
| 시계방향 제자리 회전 | HIGH | LOW | HIGH | LOW |
| 반시계방향 제자리 회전 | LOW | HIGH | LOW | HIGH |

시계방향 회전에서는 왼쪽 바퀴가 후진하고 오른쪽 바퀴가 전진한다. 반시계방향에서는 그 반대다.

## 8. 엔코더 최종 배선

### 8.1 오른쪽 엔코더

| 모터선 | ESP32 |
|---|---|
| 파란색 VCC | 3V3 |
| 검은색 GND | GND |
| 흰색 A | GPIO17 |
| 노란색 B | GPIO16 |

### 8.2 왼쪽 엔코더

| 모터선 | ESP32 |
|---|---|
| 파란색 VCC | 3V3 |
| 검은색 GND | GND |
| 흰색 A | GPIO19 |
| 노란색 B | GPIO18 |

3V3 단자 하나에 TB6612 VCC와 양쪽 엔코더 VCC를 함께 분기했다. GND 역시 공통으로 묶었다.

### 8.3 현재 사용하는 엔코더 해석 방식

A 채널의 `RISING` 에지만 인터럽트로 세고, 그 순간 B 채널을 읽어 방향을 판단한다.

```cpp
void IRAM_ATTR leftEncoderISR()
{
    int b = digitalRead(LEFT_ENC_B);

    if (b == HIGH)
        leftCount--;
    else
        leftCount++;
}

void IRAM_ATTR rightEncoderISR()
{
    int b = digitalRead(RIGHT_ENC_B);

    if (b == HIGH)
        rightCount++;
    else
        rightCount--;
}
```

최종 부호는 다음과 같다.

| 차체 동작 | 왼쪽 raw count | 오른쪽 raw count | 제어에 사용하는 진행값 |
|---|---:|---:|---|
| 전진 | 양수 | 양수 | `leftRaw`, `rightRaw` |
| 후진 | 음수 | 음수 | `-leftRaw`, `-rightRaw` |
| 시계방향 회전 | 음수 | 양수 | `-leftRaw`, `rightRaw` |
| 반시계방향 회전 | 양수 | 음수 | `leftRaw`, `-rightRaw` |

진행값 계산에 무조건 `abs()`를 사용하면 잘못된 방향으로 회전해도 정상 진행으로 오인할 수 있으므로 사용하지 않는다.

## 9. USB 업로드 시 반드시 지키는 전원 절차

USB와 강압모듈 출력이 동시에 ESP32 5V에 연결되었을 때 강압모듈 표시가 약 `4.7 V`로 켜지는 역급전 현상을 실제로 확인했다. 따라서 아래 절차를 고정 절차로 사용한다.

### 9.1 코드를 업로드할 때

1. BOOT를 누르지 않고 모터가 정지한 상태인지 확인한다.
2. 18650 배터리 한 개를 홀더에서 뺀다.
3. 강압모듈 화면과 ESP32 LED가 모두 꺼졌는지 확인한다.
4. `강압모듈 VOUT+ → ESP32 5V` 빨간선을 뺀다.
5. `VIN+ → TB6612 VM` 빨간 분기선을 뺀다.
6. 빠진 선 끝이 다른 금속이나 GND에 닿지 않게 둔다.
7. USB를 ESP32에 연결한다.
8. 정상 상태는 `ESP32 LED만 켜짐`, `강압모듈 화면 꺼짐`, `모터 정지`다.
9. 코드를 업로드하고 시리얼 시작 문구를 확인한다.

### 9.2 업로드 후 배터리 전원으로 시험할 때

1. BOOT 버튼을 누르지 않는다.
2. USB를 뺀다.
3. ESP32 LED가 꺼졌는지 확인한다.
4. `VOUT+ → ESP32 5V`를 다시 연결한다.
5. `VIN+ → TB6612 VM`을 다시 연결한다.
6. 두 선을 살짝 당겨 단단함을 확인한다.
7. 공중 시험이면 차체를 받침대에 올려 바퀴를 띄운다.
8. 배터리를 넣는다.
9. 약 5.0 V, ESP32 LED 켜짐, 모터 정지를 확인한다.
10. 주변을 비운 뒤 BOOT를 한 번 눌러 시험한다.

### 9.3 전원이 들어온 상태에서 하지 말 것

- 나사 단자를 조이거나 선을 다시 꽂지 않는다.
- VIN+와 VIN- 근처의 구리선을 손으로 정리하지 않는다.
- 모터선과 엔코더선을 바꾸지 않는다.
- 움직이는 바퀴를 손으로 붙잡지 않는다.
- USB와 강압모듈 5 V 출력을 동시에 ESP32에 공급하지 않는다.
- 사람이 없는 상태로 임시 배선 AGV를 동작시키지 않는다.

## 10. 확정된 기구 및 보정값

| 항목 | 확정값 |
|---|---:|
| 바퀴 지름 | 48 mm |
| 바퀴 이론 원주 | 약 150.8 mm |
| 좌우 바퀴 중심 간격 | 약 129~130 mm |
| 모터 엔코더 | 13 line Hall |
| 감속비 | 20:1 |
| 바퀴 1회전 | 260 count |
| 약 15 cm 직진 | 260 count |
| 약 30 cm 직진 | 520 count |
| 시계방향 제자리 90도 | 각 바퀴 176 count |
| 반시계방향 제자리 90도 | 각 바퀴 176 count |

`13 line × 20:1 = 260 count/revolution`이므로 실측값과 모터 사양이 일치한다.

48 mm 바퀴의 원주는 다음과 같다.

```text
원주 = π × 48 mm ≈ 150.8 mm
```

따라서 260카운트로 약 15 cm, 520카운트로 약 30 cm 이동하는 결과와 일치한다.

130 mm 트레드에서 양쪽 바퀴가 서로 반대로 움직이는 제자리 90도 회전의 이론 카운트는 다음과 같다.

```text
count ≈ (트레드 / (4 × 바퀴지름)) × 260
      ≈ (130 / (4 × 48)) × 260
      ≈ 176
```

실제 바닥 시험에서도 176카운트가 약 90도로 확인됐다.

## 11. RPM 및 PID 시험 결과

PWM 약 30%에서 두 모터의 속도 차이를 측정했다.

| 바퀴 | 안정 구간 속도 |
|---|---:|
| 왼쪽 | 약 151 RPM |
| 오른쪽 | 약 140 RPM |

측정 로그의 예시는 다음과 같다.

```text
LEFT Count=1602 RPM=151.3 | RIGHT Count=1484 RPM=139.8
LEFT Count=2587 RPM=151.8 | RIGHT Count=2392 RPM=139.8
FINAL LEFT COUNT  : 3242
FINAL RIGHT COUNT : 2999
```

같은 PWM에서도 왼쪽이 더 빠르다는 것이 확인됐다.

목표 140 RPM PID 시험에서 사용했던 초기 이득은 다음과 같다.

```text
Kp = 0.5
Ki = 0.2
Kd = 0.02
```

시험 결과는 대략 다음 범위에서 안정됐다.

| 바퀴 | RPM 범위 | PWM 범위 |
|---|---:|---:|
| 왼쪽 | 약 140.8~145 | 약 71~76 |
| 오른쪽 | 약 138.5~143 | 약 74~80 |

현재 최종 L자 주행 코드는 RPM PID 자체보다는 거리 카운트, 가감속 PWM 프로파일, 좌우 진행량 동기화를 사용한다. PID 시험 결과는 향후 일정한 선속도 제어에 다시 사용할 수 있다.

## 12. 대화와 실험의 전체 흐름

### 12.1 오른쪽 엔코더의 A/B 신호 확인

처음 오른쪽 엔코더를 `A=GPIO17`, `B=GPIO16`에 연결했다.

정지 중에는 다음과 같이 일정한 값이 나왔다.

```text
A=0  B=1
A=0  B=1
```

바퀴를 돌리자 `0/0`, `0/1`, `1/0`, `1/1`이 나타났다. 이 결과로 A와 B 두 채널이 실제로 들어오고 있다는 것을 확인했다.

초기 `CHANGE` 인터럽트 코드에서는 다음과 같은 왕복값이 나타났다.

```text
Count : -1
Count : 0
Count : -1
Count : 0
```

또는 다음과 같이 인접 숫자를 왕복했다.

```text
Count : 6
Count : 7
Count : 6
Count : 7
```

이는 엔코더가 완전히 죽은 것이 아니라, A의 양쪽 에지를 세면서 B 상태를 단순 판별하는 방식과 천천히 손으로 돌리는 상황이 맞지 않아 생긴 현상이었다. 이후 A의 `RISING`만 세는 방식으로 정리했다.

### 12.2 수동 방향 시험

바퀴를 앞으로 굴리면 값이 한 방향으로 누적되고, 뒤로 굴리면 반대로 돌아오는 것을 확인했다. 예를 들어 음수에서 양수까지 증가한 뒤 방향을 바꾸자 다시 감소했다.

이 단계에서 엔코더 신호 자체는 정상이라는 결론을 얻었다.

### 12.3 양쪽 엔코더 연결

오른쪽은 GPIO17/16, 왼쪽은 GPIO19/18로 연결했다.

시리얼 출력은 다음과 같이 각 바퀴를 돌릴 때 해당 값만 변했다.

```text
LEFT: 0   RIGHT: 1
LEFT: 0   RIGHT: 5
LEFT: -1  RIGHT: 2
LEFT: -7  RIGHT: 2
```

따라서 왼쪽과 오른쪽 엔코더가 독립적으로 정상 작동함을 확인했다.

### 12.4 TB6612와 배터리 배선

ESP32 터미널 어댑터를 이용해 빵판 없이 배선했다. 3V3 하나에 TB6612 VCC와 양쪽 엔코더 VCC를 분기했고, GND도 공통으로 구성했다.

2S 배터리는 TB6612 VM과 강압모듈 VIN에 공급했다. 강압모듈 출력은 5.0 V로 맞춰 ESP32 5V에 공급했다.

처음에는 안전 정지 코드로 다음 문구만 출력되게 했다.

```text
SAFE STOP READY
TB6612 STBY = LOW
```

이 상태에서 모터가 움직이지 않음을 확인한 뒤 개별 모터 시험으로 넘어갔다.

### 12.5 왼쪽과 오른쪽 모터 개별 시험

왼쪽 모터만 30%로 구동했을 때 왼쪽만 회전했다.

```text
LEFT MOTOR 30% START
LEFT MOTOR STOP
TEST FINISHED
```

오른쪽 모터도 같은 방식으로 시험했다.

```text
RIGHT MOTOR 30% START
RIGHT MOTOR STOP
TEST FINISHED
```

처음에는 두 모터가 서로 반대 방향이거나 둘 다 후진했다. 방향 핀 논리를 조정한 뒤 둘 다 차체 앞쪽으로 전진하는 것을 확인했다.

### 12.6 모터와 엔코더 동시 시험 및 부호 정규화

두 모터를 전진시켰을 때 다음 결과가 나왔다.

```text
LEFT COUNT  : -618
RIGHT COUNT : 572
```

물리적으로 두 바퀴 모두 전진했지만 왼쪽 엔코더의 부호만 음수였다. 왼쪽 ISR의 증가·감소 방향을 바꿔, 이후 전진 시 양쪽 진행값 모두 양수가 되게 정규화했다.

### 12.7 바퀴 1회전 보정

배터리를 제거하고 바퀴를 손으로 한 바퀴씩 돌렸다. 처음 바퀴 없이 조금만 돌렸을 때 20 정도만 증가했지만, 실제 48 mm 바퀴를 장착하고 정확히 한 바퀴 돌리자 양쪽 모두 약 260이 나왔다.

```text
LEFT: 261
RIGHT: 261
```

최종적으로 260카운트를 바퀴 1회전으로 확정했다.

### 12.8 RPM과 PID

30% PWM에서 왼쪽 약 151 RPM, 오른쪽 약 140 RPM으로 측정됐다. 목표 140 RPM PID 코드를 시험한 결과 양쪽 모두 목표 근처에서 안정적으로 유지됐다.

### 12.9 강압모듈 설정

강압모듈 입력에 배터리를 연결한 뒤 표시를 OUT으로 맞추고 가변저항을 돌렸다. 처음에는 7.4 V 근처였고 여러 바퀴를 돌려 5.0 V까지 내렸다.

ESP32 5V와 TB6612 VM을 연결한 뒤 배터리만으로 부팅 및 모터 시험을 수행했다. 양쪽 모터가 전진한 뒤 자동 정지했고 전압이 안정적으로 유지됐다.

USB가 연결된 상태에서 VOUT+까지 연결하면 표시가 4.7 V 정도로 켜지는 현상이 나타나 업로드 전원 분리 절차를 확립했다.

### 12.10 15 cm 직진

260카운트 목표 코드를 이용한 바닥 시험에서 실제 이동거리가 약 15 cm로 확인됐다.

### 12.11 90도 회전과 잘못된 352카운트

처음 176카운트 회전이 약 45도로 보였고, 두 번 실행하면 약 90도가 됐다. 이때 90도 목표를 352로 바꾸려고 했다.

그러나 이후 시험에서 한쪽 바퀴만 움직였다. 개별 모터 진단 코드는 다음 순서로 동작하도록 만들었다.

```text
왼쪽 모터 1.5초
→ 1초 정지
→ 오른쪽 모터 1.5초
```

처음에는 왼쪽만 돌고 오른쪽 단계에서는 아무것도 돌지 않았다. 사용자가 헐거워 빠진 점퍼선을 발견해 다시 꽂자 두 모터가 모두 정상 작동했다.

즉, 176카운트에서 45도만 돌았던 이유는 한쪽 바퀴가 정지한 상태에서 다른 바퀴만 돌아 차체가 한 바퀴를 중심으로 회전했기 때문이다. `352`는 이 고장 상태에서 나온 잘못된 보정값이었다.

선 수리 후 양쪽 바퀴를 서로 반대로 움직이는 정상 제자리 회전에서는 176카운트가 실제 약 90도로 확인됐다. 따라서 352는 폐기했다.

### 12.12 양방향 90도 회전 최종 검증

시계방향 176카운트:

- 공중에서 두 바퀴가 서로 반대로 약 2/3회전
- 양쪽 자동 정지
- 바닥에서 약 90도

반시계방향 176카운트:

- 시계방향과 반대 모터 방향
- 공중 및 바닥 시험 정상
- 바닥에서 약 90도

### 12.13 부드러운 30 cm 직진

목표를 520카운트로 설정했다. 낮은 PWM으로 출발하고, 중간에 가속하며, 도착 전에 감속했다. 양쪽 엔코더 진행량 차이로 PWM을 보정하고 먼저 도착한 바퀴는 개별 정지했다.

공중 시험에서 양쪽이 약 두 바퀴 회전 후 정지했고, 바닥에서도 약 30 cm 전진을 확인했다.

### 12.14 자동 L자 경로

검증된 세 동작을 상태기계로 합쳤다.

```text
520 count 전진
→ 1초 정지
→ 176 count 시계방향 회전
→ 1초 정지
→ 520 count 전진
→ 전체 정지
```

시작 문구는 다음과 같다.

```text
AUTONOMOUS L ROUTE READY
1: FORWARD 30CM (520)
2: CLOCKWISE 90 DEG (176)
3: FORWARD 30CM (520)
MOTORS STOPPED
PRESS BOOT ONCE TO START
```

실제 바닥 주행도 정상적으로 완료했다.

## 13. 실제로 발생했던 문제와 교훈

| 현상 | 실제 원인 또는 판단 | 해결 |
|---|---|---|
| 정지 중 `A=0 B=1` 고정 | 정상적인 디지털 상태 | 바퀴를 돌려 네 가지 상태 변화 확인 |
| 카운트가 `-1↔0`, `6↔7` 왕복 | 초기 `CHANGE` 해석 방식과 느린 수동 회전 | A의 `RISING`만 카운트하도록 변경 |
| 전진 시 왼쪽 음수, 오른쪽 양수 | 좌우 장착 방향 차이 | 왼쪽 ISR 부호 정규화 |
| 같은 PWM인데 왼쪽이 더 빠름 | 모터 개체차 및 기계적 차이 | 좌우 기본 PWM 차등 및 PID/동기 보정 |
| 176카운트가 45도로 보임 | 한쪽 모터 배선이 헐거워 한쪽 바퀴만 회전 | 점퍼선 재체결 후 176 재검증 |
| 352가 90도라고 판단 | 고장 상태를 보정값으로 오인 | 352 폐기, 176 확정 |
| 개별 시험에서 두 번째 모터 무반응 | 점퍼선 하나가 빠짐 | 선 재연결 후 두 모터 정상 확인 |
| VIN+ 선이 풀림 | 두 빨간선을 한 나사 단자에 임시 체결 | 전원 차단 후 재체결·당김 확인, 향후 분배단자 필요 |
| USB 연결 시 강압모듈에 4.7 V 표시 | ESP32 5V 쪽 역급전 | 업로드 전 VOUT+ 및 VM 분기 분리 |
| 캐스터 때문에 약간 휨 | 캐스터 방향과 바닥 마찰 | 긴 직진에서 동기제어 보정, 기계적 정렬 필요 |

가장 중요한 교훈은 예상과 다른 움직임이 나왔을 때 보정값부터 바꾸지 말고, 먼저 양쪽 모터와 엔코더가 모두 실제로 움직이는지 개별 진단해야 한다는 것이다.

## 14. 코드 발전 과정

대화 중 코드는 다음 순서로 발전했다.

1. 엔코더 A/B 디지털 상태 출력

4. TB6612 STBY LOW 안전 정지
5. 왼쪽 모터 개별 시험
6. 오른쪽 모터 개별 시험
7. 양쪽 모터 전진
8. 모터와 엔코더 동시 시험
9. 바퀴 1회전 260카운트 시험
10. 양쪽 RPM 측정
11. 목표 140 RPM PID 제어
12. BOOT 버튼 시작 및 자동 정지
13. 15 cm 직진
14. 시계방향 90도 회전
15. 반시계방향 90도 회전
16. 부드러운 30 cm 직진
17. 자동 L자 경로

최종 L자 코드에는 다음 안전 기능이 들어 있다.

- 부팅 시 STBY LOW
- BOOT 버튼 한 번으로 5초 후 출발
- 출발 대기 중 BOOT를 다시 누르면 취소
- 동작 중 BOOT를 누르면 전체 경로 중단
- 잘못된 엔코더 방향 감지
- 좌우 카운트 차이 과다 감지
- 목표 카운트 초과 감지
- 모터 또는 엔코더 정지 감지
- 동작별 시간 제한
- 먼저 목표에 도착한 바퀴 개별 정지
- 각 구간 사이 STBY LOW 및 1초 정지

## 16. 다음 단계 권장 순서

### 16.0 아직 확인되지 않은 사항

다음 항목은 대화에서 실제 측정 또는 사양 확인을 완료하지 않았다.

- 각 셀에는 보호회로 표시가 있지만 2S 팩 전체의 밸런싱/BMS 구성은 확인하지 않음
- 충전기는 사용자가 정상 작동을 확인했다고 했으며 별도 검증하지 않음
- 강압모듈 5.0 V는 표시창으로 확인했으며 독립 멀티미터 측정 기록은 없음
- MG310 모터의 실제 기동전류·스톨전류를 측정하지 않음
- TB6612의 실제 전류 여유와 발열을 장시간 시험하지 않음
- 모터 전력선과 임시 점퍼선의 굵기 및 허용전류를 확인하지 않음
- 어떤 물리적 TB6612 GND 단자를 각각 사용했는지는 기록되지 않았지만 모든 GND가 공통인 것은 확인함
- 실제 실행 프로젝트는 `EncorderTest`이며 이 문서가 저장된 Codex 작업공간은 `ESP32Test`이므로 폴더를 혼동하지 말 것

### 16.1 전원 배선 정식 마감

장시간 또는 원격 주행 전에 가장 먼저 해야 한다.

- 전원 분배단자 설치
- 퓨즈 추가
- 전원 스위치 추가
- 나사 단자 재체결
- 기판과 배터리 차체 고정
- 당김 방지와 절연 처리

### 16.2 후진 이동 검증

- 약 15 cm 또는 30 cm 후진
- 전진과 동일하게 양쪽 raw count는 음수가 되어야 함
- 진행값은 `-leftRaw`, `-rightRaw` 사용

### 16.3 오도메트리

엔코더로 다음 값을 계산한다.

```text
왼쪽 바퀴 이동거리
오른쪽 바퀴 이동거리
차체 중심 이동거리
방향각 변화
X 좌표
Y 좌표
```

핵심 기하값은 다음을 사용한다.

```text
wheelDiameter = 48 mm
wheelTrack    = 130 mm
countsPerRev  = 260
```

### 16.4 Wi-Fi 조종 및 텔레메트리

ESP32가 자체 Wi-Fi AP를 만들고 휴대폰 또는 PC 브라우저에서 다음 명령을 보낼 수 있게 한다.

- 전진
- 후진
- 좌회전 90도
- 우회전 90도
- 긴급 정지

화면에는 다음 값을 표시한다.

- 왼쪽/오른쪽 엔코더
- X, Y 좌표
- 방향각
- 현재 상태
- 오류 원인

### 16.5 PC 디지털 트윈

ESP32가 JSON 또는 WebSocket으로 위치를 보내고, PC 화면의 가상 AGV가 동일한 좌표와 방향으로 움직이게 한다.

권장 데이터 예시는 다음과 같다.

```json
{
  "x_mm": 300.0,
  "y_mm": -300.0,
  "heading_deg": -90.0,
  "left_count": 520,
  "right_count": 520,
  "state": "STOPPED"
}
```

## 17. 다음 대화를 시작할 때 보여줄 요약

새로운 대화나 다음 작업 세션에서는 아래 문장을 그대로 보여주면 된다.

```text
ESP32-WROOM-32E, TB6612FNG, MG310P20 7.4V 엔코더 모터 2개를 사용 중이다.
왼쪽 엔코더 A/B는 GPIO19/18, 오른쪽은 GPIO17/16이다.
모터 제어는 AIN1=25, AIN2=26, PWMA=27, STBY=13,
BIN1=33, BIN2=32, PWMB=14이다.
바퀴 지름 48mm, 트레드 약 130mm, 바퀴 1회전 260카운트다.
직진 30cm는 520카운트, 제자리 좌우 90도는 각 바퀴 176카운트로 검증했다.
배터리는 18650 2S, TB6612 VM은 배터리 입력,
ESP32는 LM2596 VOUT 5.0V로 공급한다.
USB 업로드 전에는 배터리를 빼고 ESP32 5V선과 TB VM 분기선을 분리해야 한다.
현재 30cm 전진→시계90도→30cm 전진 L자 경로까지 실제 바닥 시험에 성공했다.
다음 목표는 Wi-Fi 조종과 X/Y/방향각 오도메트리다.
```

## 18. 빠른 점검표

시험 전에 다음 항목을 확인한다.

- [ ] 임시 전원선이 빠지지 않는가
- [ ] VIN+와 VIN- 사이에 노출된 구리선이 없는가
- [ ] VOUT가 약 5.0 V인가
- [ ] USB와 강압모듈 출력이 동시에 ESP32 5V에 연결되지 않았는가
- [ ] TB6612 VCC는 3V3인가
- [ ] TB6612 VM은 배터리 입력 분기인가
- [ ] 공통 GND가 연결되어 있는가
- [ ] 양쪽 엔코더 커넥터가 단단한가
- [ ] 바퀴가 걸리는 전선이 없는가
- [ ] 주행 공간이 충분한가
- [ ] 사람 손이 바퀴에서 떨어져 있는가
- [ ] BOOT를 한 번만 눌렀는가
- [ ] 이상 시 배터리를 바로 뺄 수 있는가

## 19. 마지막으로 기억할 핵심

```text
1회전 = 260 count
```
